### 1.4 `@expo/metro-config` peer 문제를 푼 방법

react-native-css 3.0.7은 `@expo/metro-config`를 peer로 요구한다. 실제로 쓰는 곳은 Metro 변환기(`react-native-css/metro`의 `metro-transformer`) 하나다. 이 변환기는 JS와 CSS를 전부 Expo의 변환 워커(`unstable_transformerPath`)에 맡기고, CSS는 그 워커가 PostCSS(Tailwind)로 처리한 결과를 react-native-css 컴파일러로 RN 스타일로 바꿔 주입한다. `withNativewind`의 나머지(리졸버, CSS 확장자, 타입 파일)는 Expo와 무관하다.

**고른 방법: 같은 일을 하는 변환기를 앱에 두었다(`metro.transformer.js`, 약 40줄).** JS는 Metro 기본 워커(`metro-transform-worker` 0.87)에 그대로 넘기고, `.css`만 `postcss([@tailwindcss/postcss({ base: 프로젝트 루트 })])` → `react-native-css/compiler`의 `compile()` → `StyleCollection.inject(...)` 코드로 바꾼 뒤 기본 워커로 변환한다. `metro.config.js`는 `withNativewind(...)` 결과에서 `transformerPath`만 이 파일로 바꾼다.

- pnpm 10은 없는 peer를 자동 설치한다(auto-install-peers). 그대로 두면 `@expo/metro-config`와 `@expo/metro`·`@expo/config` 등 Expo 패키지 약 40개가 들어온다. `pnpm.packageExtensions`로 이 peer를 선택 peer로 표시해 설치되지 않게 했다. pnpm 11 이상은 package.json의 `pnpm` 필드를 읽지 않으므로(DS 구현 노트 F-20) `packageManager`의 pnpm을 올릴 때 이 설정을 `pnpm-workspace.yaml`의 `packageExtensions`로 옮긴다
- **CSS 캐시.** Tailwind 결과는 소스 파일의 클래스에 따라 바뀌지만 Metro의 캐시 키는 global.css 내용뿐이다. 그대로 두면 global.css를 고치지 않는 한 새 클래스가 번들(릴리스 포함)에 안 들어간다. 변환기가 CSS 결과에 `skipCache` 표시를 달고, `metro.config.js`의 `CssUncachedFileStore`가 그 결과를 디스크 캐시에 쓰지 않는다. Expo가 같은 문제를 같은 방식(`@expo/metro-config`의 FileStore)으로 푼다
- **남는 제약(개발 중).** 같은 Metro 세션 안에서는 다른 파일에 새 클래스를 더해도 global.css 모듈이 다시 변환되지 않는다. Expo는 Metro 그래프를 고쳐(`patchMetroGraphToSupportUncachedModules`) 매번 다시 변환하는데, 그 패치는 옮기지 않았다. 새 클래스가 안 먹으면 Metro를 다시 켠다(CSS 결과는 디스크 캐시에 없어 `--reset-cache` 없이 다시 변환된다). 내용이 같은 채로 global.css만 저장하면 Metro가 같은 모듈로 보고 넘길 수 있다. 기기에서 불편하면 그 패치를 옮긴다(1.6)

버린 대안:

| 대안 | 버린 이유 |
|---|---|
| `@expo/metro-config`를 개발 의존성으로 설치 | 57.x는 `@expo/metro`로 Metro 0.84.6을 고정한다. RN 0.87은 Metro 0.87이라, 모든 JS 파일이 서버와 다른 버전의 변환 워커를 지나게 된다. 설치해도 위의 CSS 캐시 문제는 그대로다(Expo는 자기 `getDefaultConfig`에서만 푼다) |
| Expo의 `getDefaultConfig`로 Metro 설정 전체를 바꾸기 | `expo` 패키지가 필요하다. "Expo 없이"와 어긋난다 |
| `@expo/metro-config` 이름의 가짜 패키지를 로컬에 두기 | peer 버전 검사를 속이는 방식이라 무엇을 대신하는지 코드에서 안 보인다 |

react-native-css 3.1.0-rc.0도 같은 peer를 요구하고 변환기 구조가 같다. rc.0은 변환기 옵션을 `options`가 아니라 `config.reactNativeCSS`에서 읽는데, 앱 변환기는 이미 그쪽을 읽는다.

### 1.5 Jest

- `@eeennsu`와 `lucide-react-native`는 ESM만 배포해 `transformIgnorePatterns` 허용 목록에 넣고, lucide가 주는 `.mjs`를 `babel-jest`로 변환한다(DS 구현 노트 N-14)
- `react-native-css/jest`는 `react-native` 조건에서 TS 소스를 가리킨다. `moduleNameMapper`로 CJS 빌드에 돌려 컴포넌트와 같은 인스턴스를 쓰고, tsconfig `paths`로 타입도 빌드된 `.d.ts`로 돌린다(DS 구현 노트 F-13과 같은 문제)
- `jest/css.ts`의 `registerGlobalCss()`가 global.css를 Metro 변환기와 같은 조건(Tailwind, 앱 루트 기준)으로 컴파일해 등록한다. 다크 모드는 `jest/setup.js`의 NativeAppearance 모킹과 `setColorScheme()`로 본다(DS 구현 노트 N-9)
- className으로 스타일을 주는 앱 코드는 RN 기본 컴포넌트를 `react-native`가 아니라 `react-native-css/components`에서 import한다. 앱은 Metro 폴리필 덕에 어느 쪽이든 동작하지만 Jest는 후자만 스타일을 푼다(DS 구현 노트 F-11)
- 예외는 FlatList다. `react-native-css/components`의 FlatList는 제네릭 타입이 깊어 tsc가 TS2590(유니언이 너무 복잡함)으로 멈춘다. 내역은 `react-native`의 FlatList에 className을 주고(Metro 폴리필이 푼다), 줄 안쪽은 `react-native-css/components`로 그린다
- `@react-navigation`은 ESM이라 `transformIgnorePatterns` 허용 목록에 넣었다. `jest/setup.js`가 safe-area-context(라이브러리의 Jest 모킹), 날짜 대화상자, 앱 네이티브 모듈(`SpendbackFiles`)을 모킹한다. 화면 테스트(`__tests__/screens.test.tsx`)는 앱과 같은 drizzle 드라이버를 Node 내장 SQLite(`jest/db.ts`)로 이어 실제 쿼리 위에서 화면을 그리고, 내비게이션은 이동 요청만 받는다
- CSS 등록(`registerGlobalCss()`)은 `beforeAll`이 아니라 테스트마다 그리기 직전에 한다. `react-native-css/jest`가 테스트마다 등록한 스타일을 비운다. 컴파일 결과는 캐시라 두 번째부터 빠르다

### 1.7 토스풍 전환(2026-09-25)

에뮬레이터 화면이 애매하다는 판단에서 시작했다. 원인은 세 디자인 언어가 섞여 어느 것도 강하지 않은 것이었다 — 시스템 글꼴, Tailwind 기본 팔레트와 작은 모서리, 흰 바탕 위 흰 내용. 토스 앱의 인상을 참고해 브랜치 `exp/toss-look`에서 먼저 바꿔 봤다(커밋 `6d7d0d3`: 앱 색 재선언 + 계약 밖 `@theme` 덮기 + DS 텍스트 컴포넌트에 `font-sans`를 붙이는 pnpm patch). 결과를 채택해 DS base로 옮겼고(DS 스펙 R26, 0.4.0), 이 앱은 그 base를 그대로 쓴다.

## 2. 앱 색

앱은 색을 재선언하지 않는다. DS 0.4.0 base가 이 앱의 색이다. base는 이 앱에서 한 실험(`exp/toss-look`, 1.7)을 옮긴 것이다(DS 스펙 R26, `../design-system/docs/decisions-r26.md`). 바꿀 때는 메인 색 네 개(`--bg-brand` · `--bg-brand-hover` · `--fg-on-brand` · `--fg-brand`)를 짝으로 재선언한다(C-5b). RN은 `:root`와 `@media (prefers-color-scheme: dark) { :root }` 두 블록이다(DS 알려진 동작 15).

| 역할 | 라이트 | 다크 | 쓰는 곳 |
|---|---|---|---|
| canvas | gray-100 `#f3f4f6` | zinc-950 `#09090b` | 화면 바탕. 흰 카드가 그 위에 뜬다 |
| surface | 흰색 | zinc-900 `#18181b` | Card, 시트 |
| surface-muted | gray-200 `#e5e7eb` | zinc-800 `#27272a` | 입력 칸 · 고르지 않은 칩 · secondary 버튼 채움, 다크 게이지 트랙 |
| brand | blue-550 `#206fea` | 같은 값 | 주 버튼, 고른 칩, 예산 게이지, FAB, 포커스 테두리 |
| fg-brand | blue-650 `#1b64da` | blue-400 `#51a2ff` | 브랜드 색 글자(`text-fg-brand`): "기록", 수입 금액, 회고 강조 |
| danger · fg-danger | red-600 채움 · red-700 글자 | red-600 채움 · red-400 글자 | 초과 막대 · 초과 금액. 회고 문장 속 초과 금액은 예외로 brand다(문장의 값 강조는 "코드가 채운 값"의 표시라 뜻과 상관없이 한 색이다, 8.6 036) |
| fg-muted | gray-550 `#5a6374` | zinc-400 `#9f9fa9` | 라벨, 캡션 |
| on-brand · on-danger | 흰색 | 흰색 | 채움 위 글자 |

**brand는 base 파랑이다.** 0.3.0까지는 DS 기본 파랑이 템플릿처럼 보여 채도를 낮춘 청록을 재선언했다. 에뮬레이터에서 인상이 애매하다는 판단이 나와 토스 앱 인상을 참고해 글꼴 · 층 · 모서리 · 글자 스텝을 함께 바꿨고(1.7), 그 결과 파랑이 템플릿으로 보이지 않게 되어 청록을 버렸다. 토스 파랑 `#3182F6`은 흰 글자 3.71:1이라 4.5:1을 넘는 가장 가까운 값을 쓴다.

**글자 파랑은 채움 파랑과 다른 변수다.** 다크에서 진한 파랑 위 흰 글자(4.64)와 어두운 카드 위 파랑 글자는 한 값으로 동시에 4.5:1을 넘지 못한다. 글자는 `text-fg-brand`를 쓴다. `text-brand`는 채움 색이라 다크 카드 위 3.57:1이다(DS 알려진 동작 27).

대비(WCAG 2.1. DS tokens 대비 테스트와 같은 환산):

| 조합 | 라이트 | 다크 |
|---|---|---|
| brand 위 글자(주 버튼, 고른 칩, FAB) | 4.64 | 4.64 |
| canvas · surface 위 `text-fg-brand` | 4.92 · 5.41 | 6.72(surface) |
| canvas · surface 위 muted 글자 | 5.48 · 6.02 | 6.74(surface) |
| 입력 칸 채움 위 muted 글자(placeholder) | 4.87 | 5.66 |
| canvas · surface 위 danger 글자 | 5.83 · 6.42 | 6.13(surface) |
| danger 위 흰 글자 | 4.76 | 4.76 |
| 게이지 채움 대 트랙(비텍스트 3:1. 라이트 트랙 `bg-border` gray-200, 다크 `surface-muted`) | brand 3.76 · danger 3.85 | brand 3.21 · danger 3.13 |
| 채움 위 기준선 | surface 색 테두리(2px)로 분리 | 같다 |
| 카드 대 canvas(경계는 명도 차이뿐) | 1.10 | 1.12 |
| 입력 칸 · 칩 채움 대 카드 · 시트 | 1.24 | 1.19 |
| 누르는 동안의 줄 위 muted 글자(surface-hover) | 4.09 | 3.98 |

게이지 트랙은 라이트에서 `bg-border`(gray-200)를 쓴다. 입력 칸과 칩은 테두리 대신 채움으로 보인다. 채움 대비는 비텍스트 3:1 대상으로 보지 않는다 — 입력 칸은 라벨로, 칩은 글자로 식별되고, 포커스 때 brand 테두리가 생기며 고른 칩은 brand 채움이다(DS 알려진 동작 25). 누르는 동안의 muted 글자 4.09(다크 3.98)는 손을 떼면 돌아오는 순간 상태라 그대로 둔다.

placeholder는 두지 않는다. 라벨이 칸의 뜻을 말한다(4.3). DS는 placeholder를 `fg-muted`로 칠하므로(채움 위 4.87 · 5.66) 필요해지면 넣어도 된다.

**색만으로 뜻을 전하지 않는다.** 초과는 빨강 막대와 함께 "18,000원 초과" 문구를 쓴다. 게이지는 스크린 리더 값(`accessibilityValue.text`)을 갖는다.

| 다이얼 | 값 | 이유 |

| DESIGN_EXPRESSION | 5 | 개인 핀테크(4-6)의 가운데. 굵은 금액과 회색 바탕 위 카드로 위계를 세우고(1.7), 헤더·탭 바는 canvas·surface 위 글자와 아이콘뿐인 담백한 모양이다 |

### 3.2 SAFE와 RISK

SAFE(이 앱에서 기본이 맞는 것):

- 글꼴은 Pretendard다. DS native 컴포넌트가 `font-sans`로 요청하고 앱이 Android 폰트 리소스로 등록한다(1.3)
- 중립 회색은 DS base(라이트 gray, 다크 zinc), 모서리는 DS radius(sm 8 · md 12 · lg 16 · xl 20 · full), 그림자는 DS `shadow-md` 하나(FAB)
- 아이콘은 DS가 쓰는 lucide 한 벌, 선 두께 2
- 다크 모드는 OS를 따른다(DS C-20 RN)

RISK(일부러 벗어나는 것):

| RISK | 얻는 것 | 치르는 것과 대응 |
|---|---|---|
| 예산 게이지에 오늘 기준선을 긋는다(홈의 대담한 요소) | 한 번에 "빨리 쓰는지"가 보인다 | 선만으로는 뜻이 안 전해진다. 아래에 비율과 남은 일수를 글로 쓰고 스크린 리더 값을 준다 |
| 홈 오른쪽 아래에 "기록" 확장 FAB | 입력 3탭 목표(PRD 1장)에 엄지가 바로 닿는다 | 목록 끝을 가린다. 스크롤 아래 여백 96(`pb-24`), 홈에만 둔다 |

두 선택이 부딪히는 곳은 없다. FAB는 Android의 기본 패턴이라 EXPRESSION 5와 맞는다. 0.3.0 때의 RISK 두 개(청록 brand, 홈에 카드 없음)는 1.7에서 버렸다 — 이제 DS base 그대로라 RISK가 아니다.

### 3.4 글자

| 역할 | DS 스텝 | 예 |
|---|---|---|
| 금액 히어로, 입력 시트의 금액 칸 | `2xl`(28/36/700) + `tabular-nums` | 411,600원 |
| 폼 화면의 금액 칸(월 예산, 고정비 예상 금액) | `xl`(22/30/700) + `tabular-nums` | 1,200,000 |
| 시트 제목 | `xl`(22/30/700) | 지출 기록 |
| 섹션 제목 | `lg`(18/26/600), `heading="2"` | 고정비 |
| 본문, 목록의 주 텍스트와 금액 | `md`(16/24/400) | 점심 순대국 · 9,500원 |
| 라벨, 보조 설명, 캡션 | `sm`(14/20/400), 대부분 `tone="muted"` | 식비 · 오늘 |

- 숫자는 모두 `tabular-nums`다. 금액은 어디서나 `32,000원`, 비율은 정수 %다(PRD 4.6). 사용액과 전체를 나란히 쓰는 분수 표기만 단위를 끝에 한 번 붙인다(`212,300 / 300,000원`). 12장 4번 포맷터 테스트에 넣는다
- react-native-css 3.0.7은 `font-variant-numeric`을 RN 스타일로 옮기지 않아 `tabular-nums`가 RN에서 아무 일도 하지 않는다. DS 0.3.0의 native 래퍼가 같은 클래스에 `-rn-font-variant: tabular-nums`를 더한다(RN은 문자열 `fontVariant`를 배열로 나눠 받는다, DS 구현 노트 F-21). 0.2.0 동안은 global.css에 같은 선언을 두었다
- 가장 큰 글자가 28px이다. 더 큰 표시 스텝은 DS의 5단 스케일(C-7a)을 다시 여는 일이라 만들지 않는다
- **줄은 낱말 사이에서만 바꾼다.** Android의 RN Text는 한글 음절 사이 어디서나 줄을 바꿔 "보세/요.", "않아/요."처럼 낱말이 잘린다(4차 검증 009, 에뮬레이터). iOS에는 `lineBreakStrategyIOS='hangul-word'`가 있지만 Android RN은 줄바꿈 설정(LineBreakConfig)을 넘기지 않는다. 여러 줄이 될 수 있는 문장은 `Prose`(`src/ui/prose.tsx`)로 그린다. Android에서만 낱말 안 글자 사이에 WORD JOINER(U+2060)를 넣고, 스크린 리더와 E2E는 `accessibilityLabel`의 원래 문장을 읽는다. 회고 문장의 중첩 Text도 같은 변환을 쓰고, 값 조각에 조사가 붙는 자리("배달" + "이")도 묶는다. 한 줄짜리 라벨·버튼·칩은 그대로 둔다
- 글자 크기는 사용자 설정을 끝까지 따른다. 칩 묶음은 줄을 바꿔 늘어난 글자를 받는다. 1차 검증 뒤 앱 Chip을 1.5배로 묶었다가, DS 0.3.0 재검증(WCAG 1.4.4, DS 버튼과 어긋남)에 맞춰 뺐다(1.6의 9번)

### 3.5 모양, 아이콘, 움직임

- 모서리: 입력 칸과 버튼 sm·md 12, 버튼 lg 16, 카드 20(DS Card), 시트 위 모서리 20(`rounded-t-xl`), 칩·FAB·게이지 full
- 카드는 테두리 · 그림자 없이 canvas와의 명도 차이로 뜬다. 입력 칸과 칩은 테두리 대신 채움이다(DS 0.4.0 기본값, 2장)
- 그림자는 떠 있는 요소(FAB)만. 시트는 scrim(`bg-overlay`)으로 분리한다
- 아이콘은 DS Button의 `icon`과 DS `Icon`으로만 쓴다. 이모지와 손으로 그린 SVG는 쓰지 않는다
- 움직임은 화면 전환·시트(네이티브), 누름 표시(`active:`로 표면 한 단계 진하게)뿐이다. 회고 문장은 필드가 완성될 때마다 나타나고 타자 효과는 없다(PRD 4.6)
- 누름 표시는 Android 리플이 아니라 클래스다. DS Button·Chip이 `active:opacity-80`이라 눌림 어휘를 하나로 맞춘다. 리플에 색(`android_ripple.color`)을 주면 JS 값이라 앱 색 재선언(C-5b)이 닿지 않고(DS 알려진 동작 11), 색을 빼면 테마의 중립색(`colorControlHighlight`)이라 쓸 수는 있다. 12장 6번에서는 모든 줄·헤더 버튼·탭을 클래스 눌림으로 맞췄다. 목록 줄에 색 없는 리플을 쓰는 안은 실기기에서 비교한다. 버튼과 칩은 DS의 `active:opacity-80`(색이 아니라 투명도라 className으로 바꾼 배경도 따라간다), 목록 줄과 접는 줄은 `active:bg-surface-hover`(표면이 한 단계 진해진다)
- 햅틱은 쓰지 않는다. 쓰게 되면 저장 성공에만 가벼운 진동을 준다(6장 후보)
- 떠 있는 요소(FAB)는 투명도 눌림을 쓰지 않는다. 아래 내용이 비친다(에뮬레이터 확인). 표면색으로 바꾼다(`active:bg-brand-hover active:opacity-100`)
- 상태 바 아이콘은 색 구성표를 따른다(라이트 `dark-content`, 다크 `light-content`). edge-to-edge는 상태 바를 투명하게만 하고 아이콘 색을 테마에 맡기는데, AppCompat 라이트 테마는 밝은 아이콘이라 흰 canvas 위에서 보이지 않는다. 앱 루트(`src/App.tsx`)의 `StatusBar`가 JS 뒤를 맡고, JS가 뜨기 전 첫 프레임은 앱 테마가 맡는다
- **앱 테마(`styles.xml`).** 창 배경은 canvas, `colorAccent`·`colorControlActivated`는 brand, 상태 바·내비게이션 바 아이콘은 `@bool/light_bars`(라이트 true, `values-night` false)다. 네이티브 리소스는 CSS 변수를 읽지 못해 canvas와 brand 두 값을 `res/values/colors.xml`(다크는 `values-night`)에 옮겨 적었다. 쓰는 곳은 첫 프레임의 창 배경과 Android가 그리는 스위치·날짜 대화상자 강조색뿐이다. DS base 색을 바꾸면 이 두 파일도 바꾼다(7.4)
- **앱 아이콘.** 적응형 아이콘(`mipmap-anydpi-v26`)으로 바탕은 brand, 전경은 흰 선의 "거꾸로 감는 시계"(지난 지출을 돌아본다)다. lucide `history`(ISC)의 모양을 벡터로 옮겨 안전 영역 안 42dp에 두고, Android 13 테마 아이콘(monochrome)도 같은 그림을 쓴다. Android 12+ 스플래시도 이 아이콘을 창 배경(canvas) 위에 띄운다. 7.1 이하(API 24·25)는 템플릿의 PNG가 그대로다

### 3.7 접근성

- 누름 영역은 48dp 이상이다. 칩은 38 + 세로 hitSlop 5, 목록 줄은 줄 전체다. DS Button sm(30)·md(42)는 세로 hitSlop(9·3)과 최소 폭 48로 채운다. 세로로 쌓으면 hitSlop이 겹치지 않게 sm은 18, md는 6 이상 띄운다(DS 알려진 동작 18). DS Input은 hitSlop이 없어 입력 칸은 모두 `lg`(48)로 둔다(메모, 예산, 이름 칸. 1.6의 20번은 12장 6번에서 닫았다)
- 저장이 눌리지 않을 때는 이유를 저장 위에 한 줄로 쓰고, live region이라 바뀌면 스크린 리더가 알린다("금액을 입력해 주세요", "카테고리를 골라 주세요")
- 스위치가 있는 줄은 줄 전체가 스위치다(`accessibilityRole="switch"`, 글자를 눌러도 켜진다). 동작이 둘인 줄(카테고리: 이름 바꾸기와 입력에 보이기)만 예외로, 줄 전체를 스위치로 만들지 않고 연필 버튼("식비 이름 바꾸기")과 스위치("식비 입력에 보이기")에 이름을 따로 준다(4차 006)
- 입력 칸은 모두 보이는 라벨(DS `Label`)을 단다. DS Input의 `label`은 스크린 리더 이름일 뿐이다(4차 007)
- 하나만 고르는 칩 묶음에 라디오 그룹 의미는 없다. DS Chip이 토글이라서다(DS 알려진 동작 19). 칩마다 "선택됨"은 읽힌다
- 같은 이름의 버튼을 두지 않는다. 홈의 고정비 줄은 "휴대폰 요금 기록, 21일 결제 · 예상 55,000원"처럼 줄마다 이름이 다르다
- 게이지는 `progressbar` 역할과 읽을 값(`accessibilityValue.text`)을 갖는다
- 섹션 제목은 `heading`(스크린 리더의 제목 이동), 접는 영역은 `expanded` 상태를 알린다
- 시트가 떠 있으면 뒤의 화면을 스크린 리더에서 숨긴다. 시트는 투명 모달 화면이라 뒤 화면이 같은 창에 남는데, react-native-screens가 투명한 맨 위 화면 아래의 화면들을 `no-hide-descendants`와 포커스 막기로 숨긴다(`ScreenStack.updateA11yForVisibleScreens`). scrim은 스크린 리더에서 빼고 시트 안의 "닫기"로 닫는다
- live region은 내용과 함께 새로 붙이지 않는다. 늘 있는 View 안에서 글자만 바꿔야 처음 바뀐 내용도 읽힌다(입력 시트의 저장 줄, 백업 결과, 회고 상태 줄, 5차 021)
- 접근성 prop만 가진 래퍼 View(live region 등)에는 `collapsable={false}`를 준다. New Architecture가 스타일·이벤트 없는 View를 평탄화해 prop이 기기에 닿지 않는다. Jest 트리에는 남아 테스트가 통과하므로 `collapsable` 단언을 따로 둔다. 회고 스트리밍 상태도 같다

### 3.8 문구

- 해요체, 담백하게. 느낌표, 이모지, 인사 머리말("안녕하세요!")을 쓰지 않는다
- 화면 문자열에 em-dash(`—`)를 쓰지 않는다. 구분은 가운뎃점(`·`)이다
- 날짜는 "오늘", "어제", 그 전은 "9월 22일"이다
- 가짜 데이터도 실제처럼 쓴다(점심 순대국 9,500원, 다이소 수납함 7,000원). 이름 없는 "Item 1"이나 딱 떨어지는 숫자만 쓰지 않는다

### 4.2 홈

위에서부터 행동이 필요한 것 → 참고할 것 순서다.

1. **남은 예산**: "남은 예산"(sm muted) → 금액(2xl) → 소비 속도 한 줄(md, 할 수 있는 일이라 금액 바로 밑) → 예산 게이지(오늘 세로선) → "788,400원 사용 · 66% | 예산 1,200,000원"(sm muted, 좁으면 두 줄) → "세로선은 오늘이에요 · 이번 달 80% 지남"(sm muted, 세로선의 뜻). 달은 헤더("9월")가 맡아 제목에 달을 쓰지 않는다. 총예산을 넘으면 제목이 "예산", 금액이 "18,000원 초과"(danger), 소비 속도가 "남은 7일 · 지금부터 쓰는 만큼 초과가 늘어요", 게이지가 꽉 찬 danger다. 예산이 없으면 "아직 예산이 없어요" + "예산을 정하면 남은 금액과 쓰는 속도를 여기에 보여 줘요" + "예산 정하기". 히어로 전체가 버튼이고 예산 화면을 연다(4.1)
2. **고정비**: 제목 옆 "5개 중 3개 기록", 결제일이 오늘이거나 지났는데 기록하지 않은 항목만 줄로. 줄 전체가 버튼이고 이름은 줄마다 다르다("휴대폰 요금 기록, ..."). 결제일 오름차순(오래 밀린 것 먼저)이다. 누르면 채워진 입력 시트(PRD 4.4, 4.3). 모두 기록했으면 "이번 달 고정비를 모두 기록했어요", 아직 결제일이 오지 않았으면 "결제일이 오면 여기에서 알려 줘요" 한 줄로 알린다. 밀린 항목이 있으면 줄 위에 "결제일이 오늘이거나 지났는데 아직 기록하지 않았어요"를 쓴다. 등록한 항목이 없으면 섹션을 두지 않는다
3. **카드 알림**(PRD 4.9): 제목 옆 "3건", 아래에 "확인하고 저장해야 기록돼요"(sm muted). 대기 중인 알림만 줄로, 결제일이 늦은 것 먼저다. 승인은 가맹점(한 줄) · "카페·간식 추천 · 오늘" · 오른쪽에 금액과 그 아래 brand "기록"이고(고정비 줄과 같다. 저장 전 줄이 최근 지출 줄과 같은 모양이 되지 않게, 7차 038), 스크린 리더 이름은 "스타벅스 역삼점 기록, …"이다. 추천이 없으면 "카테고리 고르기", 모델이 있고 아직 묻지 않았으면 "추천 준비 중", 같은 날 같은 금액의 지출이 있으면 맨 앞에 "이미 기록했을 수 있어요"다(저장 전에 알아야 하는 것이라 앞). 메타가 두 줄이 되면 낱말 사이에서만 바뀐다(3.4). 누르면 채운 입력 시트(4.3). 취소는 "결제 취소 · 스타벅스 역삼점" · "어제 기록을 지울까요?"(날짜는 3.8의 상대 표기) · 금액이고, 누르면 대화상자("닫기"(cancel) · "기록 두기" · "지우기"(destructive))다. 짝이 없으면 "짝을 찾지 못했어요 · 내역에서 고쳐 주세요"이고 누르면 "닫기" · "넘기기"다. 읽지 못한 알림은 "읽지 못한 알림 · 카드 이름" · 원문 두 줄이고, 누르면 원문(제목이 카드 이름을 말하므로 본문은 원문만)과 "닫기" · "직접 기록"(알림을 치우고 빈 입력 시트) · "넘기기"다. 내용을 보이는 데 대화상자를 쓰는 것은 3.6의 예외다. 원문은 한 번 보고 넘기거나 직접 적는 것이라 화면을 두지 않는다. 대기 중인 알림이 없으면 섹션을 두지 않는다. 고정비 다음에 두는 것은 둘 다 기록을 기다리는 줄이어서다
4. **카테고리 예산**: 예산을 정한 카테고리만. 이름, "212,300 / 300,000원", 얇은 게이지. 넘으면 danger 글자 "18,000원 초과"와 꽉 찬 danger 막대
5. **최근 지출**: 5줄. 메모(한 줄, 넘치면 말줄임) · "식비 · 오늘" · 금액. 메모가 없으면 제목이 카테고리이고 아랫줄은 날짜만이다(같은 말을 두 번 쓰지 않는다). 누르면 수정 시트. 목록 끝에 "내역 전체 보기"(secondary). 기록이 없으면 "아직 기록이 없어요. 오른쪽 아래 기록 버튼으로 첫 지출을 남겨 보세요"
6. **기록 FAB**: 오른쪽 아래, 확장형(아이콘 + "기록")

소비 속도는 PRD 4.3의 식을 따른다. 남은 일수는 오늘을 포함하고(9월 24일이면 7일), 하루 쓸 수 있는 금액은 남은 예산 ÷ 남은 일수를 원 단위로 내린 값이다("남은 7일 · 하루 58,800원까지 쓸 수 있어요"). 게이지 기준선은 오늘이 끝날 때까지의 몫(24 ÷ 30 = 80%)이다.

### 4.3 입력 시트

PRD 4.1의 3탭(금액 → 카테고리 → 저장)이 기준이다.

1. 손잡이, 제목 "지출 기록"(수입이면 "수입 기록", 수정이면 "지출 수정"), 오른쪽 "닫기"
2. **금액**: 라벨 "금액", 큰 입력 칸(`kind="number"`, 2xl, 고정폭 숫자, 천 단위 쉼표) + "원". 시트가 열리면 이 칸에 포커스가 가고(DS Input의 `ref`로 `focus()`) 숫자 키패드가 뜬다. 키패드가 뜨면 시트가 그만큼 올라가고, 넘치는 만큼 가운데 스크롤이 줄어 제목과 저장이 늘 보인다
3. **카테고리**: 칩 11개(수입이면 3개), 줄 바꿈. 고른 칩은 brand로 채운다
4. **날짜**: "오늘"(기본) · "어제" · "다른 날"(Android 날짜 대화상자). 다른 날을 고르면 그 칩이 "9월 20일"로 바뀐다
5. **선택 항목 더 보기**(접힘): 누르면 펼쳐지고 아래 줄에 무엇이 들어 있는지 적는다. 오른쪽 꺾쇠(`chevron-down` · `chevron-up`)가 펼침을 알린다. 펼치면 키보드를 내리고 펼친 줄을 시트 위쪽으로 스크롤해 새로 생긴 항목이 보이고, 아래 버튼 영역 위에 경계선(`border-t border-border`)을 긋는다(4차 001·014). 구분(지출/수입) · 이유 · 만족도 · 메모(과거 메모 제안 칩, 고르면 전에 쓴 카테고리도 고른다) · 결제수단 · 고정비(스위치, 켜면 고정비 항목 칩)
6. **저장**: 아래 고정, 키보드가 떠도 보인다. 금액과 카테고리가 있어야 눌리고, 눌리지 않으면 그 이유를, 눌리면 저장할 날짜("오늘 날짜로 저장해요")를 위에 한 줄로 쓴다. 키보드가 떠 날짜 칩이 가려져도 기본값 "오늘"이 보인다(5차 020). 가운데가 넘쳐 스크롤되면(펼쳤거나 키보드가 떠 날짜 줄이 잘리면) 아래 버튼 영역 위에 경계선을 긋는다

**시트를 띄우는 방법(12장 6번에서 바꿨다).** 처음에는 React Navigation의 `formSheet`로 띄웠다. 키보드가 뜨면 네이티브가 시트를 위로 옮기는데, JS의 `measureInWindow`는 그 이동을 몰라 시트 위쪽을 실제(74dp)와 다른 194dp로 쟀다(에뮬레이터). 그래서 `KeyboardAvoidingView`에 넘길 위치를 구할 수 없었고 저장이 키패드에 가렸다. 지금은 투명 모달(`presentation: 'transparentModal'`, `animation: 'fade'`) 위에 앱의 `Sheet`(`src/ui/sheet.tsx`)를 그린다. 모달은 창 전체라 `KeyboardAvoidingView`(behavior padding)가 그대로 맞는다.

- scrim(`bg-overlay`)은 화면 전체이고 누르면 닫는다. 시트 위로 부모 화면이 48만큼 보이게 상태 바 높이 + 48을 비운다(펼친 시트가 상태 바 아래로 파고들지 않는다)
- 시트는 `rounded-t-xl bg-surface`, 다크에서 테두리. 접힌 시트는 내용 높이(`max-h-full`), 펼치면 남은 높이를 다 쓰고(`flex-1`) 가운데 스크롤이 넘치는 만큼 줄어 제목과 저장이 늘 보인다
- 키보드가 떠 있으면 아래 내비게이션 바 자리를 비우지 않는다(키보드가 그 자리를 덮는다)
- 닫기는 "닫기", scrim, 뒤로 가기, 끌기 넷이다. 손잡이와 제목 줄을 아래로 120dp 넘게(또는 빠르게) 끌면 닫고, 덜 끌면 제자리로 돌아온다(RN PanResponder, 의존성 없음). 넷 모두 같은 onClose로 모여 입력이 있으면 버릴지 묻고, "계속 입력"이면 시트가 돌아온다. 끄는 영역을 손잡이·제목 줄로 한정해 가운데 스크롤과 다투지 않는다

- 고정비를 켜면 "연결할 고정비 항목" 칩(등록한 항목)이 나온다. 스위치 줄은 글자를 눌러도 켜진다
- 입력 칸에 placeholder를 두지 않는다(2장). 라벨이 칸의 뜻을 말한다
- 이유·만족도·결제수단은 고른 칩을 다시 누르면 선택이 풀린다. 필수(카테고리, 날짜, 구분)는 풀리지 않는다. 결제수단은 미리 고르지 않는다(PRD 4.1에 기본값이 없다)
- 메모 제안 칩은 3개까지다(과거 메모 수만큼 늘지 않게). 칸이 비면 최근 메모 3개, 입력하면 그 글자를 포함하는 과거 메모 중 최근 3개다
- 수입으로 바꾸면 카테고리 선택이 비고 지출 전용 항목(이유, 만족도, 고정비)이 사라진다
- 수정 모드는 선택 항목 아래, 접힘 밖에 "삭제"(danger, 확인 대화상자)를 둔다. 펼치지 않아도 찾는다(5차 030)
- 홈 고정비 줄에서 열면(PRD 4.4) 채워진 채로 연다. 제목 "휴대폰 요금 기록", 금액은 예상 금액, 카테고리는 항목의 카테고리, 날짜 칩은 결제일("9월 21일")이다. 메모와 고정비 연결은 선택 항목 안에 있으므로, 선택 항목에 값이 있으면 접힌 줄의 요약이 항목 이름 대신 값을 보인다("휴대폰 요금 · 고정비 연결"). 사용자는 금액만 고치고 저장한다
- 입력이 있는 채로 닫기·scrim·뒤로 가기를 하면 버릴지 묻는다(React Navigation `usePreventRemove`)
- 홈 카드 알림 줄에서 열면(PRD 4.9) 제목은 고정비 시트처럼 가맹점 이름("스타벅스 역삼점 기록", 7차 047)이고, 금액·날짜는 알림 값, 메모는 가맹점, 결제수단은 카드, 카테고리는 추천을 고른 채 연다. 금액이 채워져 있어 키패드를 띄우지 않는다. 카테고리 칩 아래에 추천이 어디서 왔는지 한 줄로 쓴다("전에 이 가맹점을 카페·간식에 적었어요", "배달은 기기 안 모델의 추천이에요. 맞는지 확인해 주세요"). 앞은 사실이고 뒤는 확인을 부탁하는 말이다. 가맹점명이 결제대행사(토스의 "비바리퍼블리카" 등)면 추천 없이 카테고리를 비운 채 열고 그 자리에 "결제대행사라 가게를 알 수 없어요"를 쓴다(PRD 4.9). 메모(대행사 이름)를 가게 이름으로 고쳐 저장하면 다음 추천의 자료가 된다. 같은 날 같은 금액의 지출이 있으면 그 아래에 "같은 날 같은 금액의 지출이 이미 있어요. 같은 결제라면 기록 안 함을 눌러 주세요"를 쓴다. 추천이 시트를 연 뒤에 오면(홈에서 모델이 아직 보는 중) 아직 카테고리를 고르지 않았을 때만 고른다. "기록 안 함"(secondary, lg)은 아래 버튼 영역에서 저장 왼쪽에 있다. 겹친 기록 안내가 가리키는 버튼이라 스크롤 끝에 두면 그 안내가 보일 때 버튼이 화면 밖이었다(7차 037)

**스크롤 끝.** 스택 화면의 스크롤은 `ScreenScroll`(`src/ui/layout.tsx`)이고, 아래 끝에 내비게이션 바 높이만큼 더 비워 3버튼 내비게이션에서도 마지막 버튼이 막대에 걸리지 않는다(4차 011). `contentContainerStyle`을 주면 react-native-css가 `contentContainerClassName`의 여백을 덮어써(에뮬레이터에서 카드 좌우 여백이 사라졌다) 빈 뷰로 비운다. 카드 안 줄 묶음은 간격 없는 View로 감싸 줄 간격을 줄 자신의 여백(48/72)으로만 둔다(4차 010).

**폼 화면과 키보드.** 입력 칸이 있는 스택 화면(예산, 고정비 항목, 카테고리)은 `FormFrame`(`src/ui/keyboard.tsx`) 위에 그린다. edge-to-edge에서는 키보드가 떠도 창이 줄지 않아, 그대로 두면 아래 칸과 저장이 키보드에 가린다. `KeyboardAvoidingView`(padding)가 내용을 올리고, 가운데 스크롤이 줄며 포커스한 칸이 보이게 스크롤된다. 키보드가 없을 때는 아래 버튼이 제스처 막대에 걸치지 않게 안전 영역을 비운다.

회고 문장에서 코드가 채운 값(금액·비율·이름)은 `text-fg-brand`와 고정폭 숫자로 강조한다. 서술어 값("39,200원 늘었어요")은 숫자까지만 칠하고 "늘었어요"는 문장 글자로 둔다(에뮬레이터에서 서술어까지 칠해져 동사가 강조돼 보였다). "숫자는 코드가 쓴다"(PRD 2장)가 화면에서 보이게 하는 장치이고 회고 상세의 대담한 요소다. DS Text는 문자열만 받아(DS 알려진 동작 6) 이 부분은 중첩 RN Text로 앱이 만든다.

차트는 react-native-svg로 그린다(`src/ui/charts.tsx`, PRD 13장). 조각 5~6개와 막대 7~31개라 Skia·victory-native가 필요 없고, DS 아이콘이 이미 react-native-svg를 쓴다. 색은 JS 값이 아니라 DS 클래스(`stroke-brand`, `fill-fg-muted`)를 react-native-css의 `useCssElement`가 SVG prop(stroke, fill)으로 옮긴다. 그래서 다크 모드와 DS 색 변경을 따라간다. 도넛은 가장 큰 조각만 brand, 나머지는 `fg-muted`의 투명도 단계이고, 5% 이상 조각에 %(14)를 적는다. 표의 줄 앞에 조각과 같은 색 견본(`Swatch`, 회색 견본은 `border` 테두리)을 두어 같은 %가 둘이어도 조각과 줄이 이어진다. 조각 사이에는 카드 바탕색(`stroke-surface`) 틈을 그어 옅은 회색 조각끼리도 경계가 보인다(5차 028). 일별 막대는 가장 많이 쓴 날만 brand이고, 회색 막대는 카드 바탕과 3:1을 넘게 투명도 0.7이다(계산값 라이트 약 3.1, 다크 약 4). 막대 아래에 "가장 많이 쓴 날은 …"을 글로 쓴다. 도넛과 막대 그림은 스크린 리더에서 숨기고 표와 그 글이 읽힌다(4차 004).

### 7.2 스킬 기본값을 바꾼 것

- 문서: MOBILE-DESIGN.md, `design-system/<이름>/MASTER.md` 대신 이 문서 하나
- 토큰: tailwind.config·`theme/tokens.ts`를 만들지 않는다. 색은 global.css의 C-5b 재선언만, 간격은 DS 키 안에서, 글자·모서리·글꼴은 DS 그대로
- 스택: Expo·Expo Router → RN CLI·React Navigation 7, React Native Reusables → `@eeennsu/native`, expo-haptics → 없음(6장 후보), expo-font → 시스템 글꼴(1.7에서 Pretendard를 Android 폰트 리소스로 등록)
- ui-ux-pro-max `--design-system` 결과 중 글꼴 추천(Caveat·Quicksand, 손글씨 계열)과 스타일 추천(Glassmorphism)은 한국어 가계부와 맞지 않고 mobile-taste의 블러 금지와 부딪혀 버렸다. 쓴 것은 제품 추천("차분한 주색 + 성공 초록 + 경고 빨강")과 차트 규칙(도넛 5~6조각 이하, 직접 라벨, 표 대체), 폼 규칙(보이는 라벨, 점진 공개), 접근성 규칙이다
- `--persist`는 쓰지 않았다

### 7.3 PRD와 부딪힌 스킬 규칙

### 7.4 12장 6번(UI)에서 정한 것

| 지점 | 고른 것 | 버린 것과 이유 |
|---|---|---|
| 헤더 · 탭 바 | 앱이 DS 클래스로 그린다(4.1) | React Navigation 기본 헤더·탭 바는 색을 테마 객체(JS 값)로 받는다. DS 색을 쓰려면 앱이 색 값을 한 벌 더 들고 다크 모드도 따로 맞춰야 한다(2장의 "앱은 색을 재선언하지 않는다"와 어긋남) |
| 바텀 시트 | 투명 모달 + 앱 `Sheet`(4.3) | formSheet는 키보드가 뜰 때 시트 위치를 JS가 잴 수 없어 저장이 가렸다(에뮬레이터). `@gorhom/bottom-sheet`는 gesture-handler까지 두 의존성이 늘어 보류(6장) |
| 차트 | react-native-svg + DS 클래스 색(4.4) | victory-native + Skia는 차트 두 개에 비해 크고 색을 JS 값으로 받는다(PRD 13장) |
| 화면 데이터 | 쓰기가 데이터 버전을 올리고 화면 쿼리가 다시 읽는다(`src/state/data.ts`) | 로컬 SQLite 쿼리가 짧아 화면마다 다시 읽어도 된다. 쿼리 구독 계층을 따로 두지 않는다 |
| 목록 | RN FlatList에 className(1.5) | react-native-css FlatList는 tsc가 TS2590으로 멈춘다 |
| 앱 테마 색 | canvas·brand 두 값을 네이티브 리소스에 옮겨 적는다(3.5) | 1·3차 검증에서 "색을 DS 밖에 한 벌 더 둔다"며 미뤘다. 첫 프레임의 창 배경과 Android가 그리는 스위치·날짜 대화상자는 CSS 변수를 읽을 수 없어 다른 길이 없다. 두 값만, 쓰는 곳을 주석에 적었다 |
