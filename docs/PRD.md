# spendback PRD

> 상태: 초안 v0.1 · 2026-09-24 · 기획 인터뷰로 합의한 초기 기획

## 1. 개요

spendback은 온디바이스 LLM이 소비 회고를 써 주는 Android 가계부다. 지출을 폼으로 빠르게 기록하면, 한 주나 한 달이 끝났을 때 코드가 소비 지표를 계산하고 로컬 LLM이 그 지표로 회고 문장을 쓴다. 데이터와 모델은 모두 기기 안에만 있다.

- 사용자: 개발자 본인 1명(Galaxy S24+)
- 형태: React Native CLI(New Architecture) Android 앱, 포트폴리오 프로젝트
- 언어·통화: 한국어, 원화(원 단위 정수)

### 포트폴리오로 보여줄 것

1. **온디바이스 LLM 통합**: 모델 다운로드, 로드, 스트리밍, 해제
2. **LLM과 코드의 경계 설계**: LLM이 숫자를 만들 수 없는 구조를 만들고, 평가 하네스로 증명
3. **제품·UX 완성도**: 3번 탭으로 끝나는 입력, 읽히는 회고

## 2. 핵심 원칙: 계산은 코드가, 문장 생성과 입력 구조화는 LLM이

| 역할 | 담당 | 적용 시점 |
|---|---|---|
| 합산, 비율, 증감, 예산 대비, 날짜 계산, 금액 표기 | 코드 | MVP |
| 어떤 사실을 골라 어떤 순서로 말할지, 연결 문장, 제안 | LLM | MVP(회고) |
| 비정형 텍스트를 거래로 구조화 | LLM + 코드 검증 | 2단계(카드 알림 파싱) |

코드가 계산해 LLM에 넘기는 지표 묶음을 **facts**라 부른다. 원칙을 지키는 장치는 네 가지다.

- LLM은 숫자를 직접 쓰지 않는다. 금액, 비율, 횟수, 증감 표현은 전부 `{키}` 플레이스홀더로 참조하고, 값은 코드가 채운다.
- llama.rn의 출력 문법(GBNF)으로 숫자 문자와 facts에 없는 키를 원천 차단한다.
- 문법으로 막을 수 없는 한글 수사("삼만 원", "두 배")는 코드가 사후 검사하고, 걸리면 재생성한다.
- 직전 기간 데이터가 없으면 비교 키를 facts에 넣지 않는다. 그러면 LLM이 비교 문장을 쓸 수 없다.

## 3. 범위

### MVP

- 폼 입력(지출·수입), 내역 편집·삭제
- 카테고리·이유 태그 편집
- 달력 월 예산(월 총예산 + 선택형 카테고리 예산)
- 주간·월간 회고(지표, 차트, LLM 문장)
- 모델 다운로드·교체
- JSON 내보내기·가져오기
- LLM 평가 하네스(PC 로컬 스크립트)

### 2단계 이후(우선순위 순)

1. **카드 알림 파싱**: Android `NotificationListenerService` 네이티브 모듈로 알림을 받고, LLM이 거래로 구조화하고, 사용자가 폼에서 확인한 뒤 저장한다. 핵심 원칙의 "입력 구조화"가 처음 적용되는 기능이다.
2. **다짐 루프**: 회고 끝에 다음 기간 다짐을 남기고, 다음 회고에서 코드가 달성 여부를 판정한다.
3. **대화형 질의**: "이번 달 배달 얼마 썼어?" 같은 질문을 LLM이 질의로 구조화하고, 코드가 계산한다.
4. **보안**: 앱 잠금(생체 인증), DB 암호화(SQLCipher)

### 범위 밖

- 자연어 입력, 영수증 OCR, 음성 입력, CSV 가져오기
- iOS, 서버·동기화·계정, 다국어·다중 통화
- 할부, 반복 거래 자동 생성

## 4. 주요 기능

### 4.1 입력(하단 시트 폼)

목표는 금액 → 카테고리 → 저장, 3번 탭이다.

| 필드 | 필수 | 규칙 |
|---|---|---|
| 금액 | 필수 | 숫자 키패드. 원 단위 양의 정수 |
| 카테고리 | 필수 | 칩 선택. 지출/수입 전환에 따라 목록이 바뀜 |
| 날짜 | 기본값 오늘 | "어제" 칩, 그 외는 날짜 선택기 |
| 지출/수입 | 기본값 지출 | 접힌 영역 |
| 이유 태그 | 선택 | 1개. 지출만 |
| 만족도 | 선택 | 후회 / 보통 / 만족. 지출만 |
| 메모 | 선택 | 과거 메모 자동완성. 같은 메모에 전에 고른 카테고리를 자동 선택(코드) |
| 결제수단 | 선택 | 카드 / 현금 / 계좌이체 |
| 고정비 | 기본값 끔 | 월세·구독 등. 회고에서 변동비와 분리 |

결제가 취소되면 거래를 삭제한다.

### 4.2 카테고리와 이유 태그

- 지출 카테고리 기본 11개: 식비, 카페·간식, 배달, 교통, 쇼핑, 생활, 주거·통신, 문화·여가, 의료·건강, 경조사·선물, 기타
- 수입 카테고리 기본 3개: 급여, 부수입, 기타
- 이유 태그 기본 6개: 필요, 충동, 보상·스트레스, 약속·사교, 습관, 선물
- 모두 추가와 이름 변경이 가능하다. 삭제는 숨김으로 처리해 과거 거래와 집계를 보존한다.

### 4.3 예산

- 기준 기간은 달력 월(1일~말일) 하나다. 시작일 설정은 없다.
- 월 총예산을 두고, 카테고리별 예산은 선택이다.
- 주간 예산은 해당 주의 날짜마다 "그 달 예산 ÷ 그 달 일수"를 더해 구한다. 두 달에 걸친 주도 같은 규칙을 쓰고, 카테고리 예산도 같다.
- 홈에서는 진행 중인 달의 예산 소진율과 남은 일수 대비 소비 속도를 보여준다.

### 4.4 내역

날짜별로 묶은 목록, 필터(기간 / 카테고리 / 태그 / 지출·수입), 편집·삭제.

### 4.5 회고

**기간**: 주간(월~일)과 월간(달력 월). 비교 대상인 직전 기간은 바로 앞 주, 바로 앞 달이다.

**생성 조건**

- 끝난 기간만 생성한다. 진행 중인 기간은 지표와 차트만 보여준다.
- 기간 안의 지출 기록이 3건 미만이면 LLM을 부르지 않고 "기록이 부족해요"라고 안내한다.
- 회고 화면을 열 때 생성하고 스트리밍으로 보여준다. 생성 중 취소와 재생성을 지원한다.

**facts(코드 계산)**

| 지표 | 주간 | 월간 |
|---|---|---|
| 총지출(변동비·고정비 분리) | O | O |
| 직전 기간 대비 증감액·증감률 | O | O |
| 카테고리별 합계·비중, 증감 상위 3개 | O | O |
| 예산 대비 사용률, 초과·잔여 금액(총예산·카테고리 예산) | O(일할 예산) | O |
| 이유 태그별 합계·비중 | O | O |
| "후회" 만족도가 붙은 지출 합계 | O | O |
| 최대 단일 지출 | O | O |
| 무지출일 수 | O | O |
| 지출이 가장 많은 요일 | O(가장 많이 쓴 날) | O |
| 같은 메모가 반복된 지출 상위 3개(메모 완전 일치 기준) | O | O |
| 수입 대비 지출률(그 달에 수입 기록이 있을 때만) | - | O |

회고는 끝난 기간만 다루므로 "남은 일수 대비 소비 속도"는 회고 지표가 아니라 홈 지표다.

**출력 형식**

LLM은 아래 JSON만 출력한다. `insights`는 2~4개다.

```json
{ "headline": "...", "insights": ["...", "..."], "suggestion": "..." }
```

- 문장 안의 수치와 증감은 플레이스홀더로만 쓴다. 예를 들어 LLM이 `배달이 {category.delivery.change_phrase}. 전체 지출의 {category.delivery.share}를 차지했어요.`라고 쓰면, 코드가 `배달이 32,000원 늘었어요. 전체 지출의 18%를 차지했어요.`로 채운다.
- 증감 방향도 계산 결과이므로 "늘었어요 / 줄었어요 / 같았어요"까지 코드가 채운다.
- 요청할 때마다 facts의 키 목록으로 GBNF 문법을 만든다. 문장에 쓸 수 있는 문자에서 숫자(0-9)와 `%`를 뺀다.
- 사후 검사에서 한글 수사와 단위의 조합("삼만 원", "두 배", "세 번" 등)이 나오면 재생성한다. 재시도는 최대 2회이고, 그래도 실패하면 폴백으로 넘어간다.
- 금액은 어디서나 `32,000원` 형식으로 표기하고, 비율은 정수 %로 표기한다. 반올림 규칙은 코드에 두고 단위 테스트로 고정한다.

**저장**: facts 스냅샷, 출력 JSON, 모델 ID, 프롬프트 버전, 생성 시각을 함께 저장한다. 과거 회고는 목록에서 다시 열람할 수 있다.

**톤**: 담백한 분석가. 마지막에 제안 한 줄을 붙인다.

**폴백**: 모델이 없거나, 로드에 실패하거나, 사후 검사가 반복 실패하면 지표와 차트만 보여주고 "모델을 받으면 회고 문장이 생성됩니다"라고 안내한다.

### 4.6 모델 관리(설정)

- 레지스트리에 등록된 모델 목록을 보여주고, 다운로드, 삭제, 사용 모델 선택을 지원한다.
- 다운로드는 Hugging Face에서 받는다. 진행률 표시, 이어받기, SHA-256 검증, 저장 공간 확인을 붙이고 Wi-Fi 사용을 권장한다.
- 개발 빌드에는 기기의 로컬 파일 경로에서 모델을 로드하는 옵션을 둔다.

### 4.7 백업

JSON 내보내기·가져오기. 파일은 Android 공유 시트로 주고받는다. 가져올 때 스키마 버전을 확인하고 Zod로 검증한다.

## 5. 화면 구성

탭은 4개다.

| 탭 | 내용 |
|---|---|
| 홈 | 이번 달 예산 게이지(총예산·카테고리), 소비 속도, 최근 지출, 입력 버튼(하단 시트 폼을 연다) |
| 내역 | 목록, 필터, 편집·삭제 |
| 회고 | 주간/월간 목록 → 상세(스트리밍 문장, 카테고리 도넛 차트, 일별 막대 차트) |
| 설정 | 카테고리·태그 편집, 예산, 모델 관리, 백업 |

## 6. LLM 설계

### 런타임

- llama.rn 0.12.x를 정확한 버전으로 고정한다. npm `latest` 태그가 RC 버전을 가리키고 있어서 `^` 범위 지정을 쓰지 않는다.
- 대상 기기는 국내판 S24+(Exynos 2400)로 **가정**한다. 이 경우 llama.rn의 GPU 가속(OpenCL, Adreno 전용)과 NPU 가속(Hexagon)을 쓸 수 없어 CPU 추론이 전제다.
- Gemini Nano는 사용자의 S24+에서 쓸 수 없다(사용자 확인).

### 모델 레지스트리

| 모델 | 크기(Q4_K_M) | 라이선스 | 비고 |
|---|---|---|---|
| Qwen3.5-2B | 약 1.28GB | Apache-2.0 | 잠정 기본값 |
| Kanana-1.5-2.1B | 약 1.52GB | Apache-2.0 | 한국어 특화 |
| EXAONE 4.0 1.2B | 약 0.81GB | 비상업, 재배포 금지 | 개인용. 앱은 Hugging Face에서 받기만 한다 |

기본 모델은 평가 하네스 결과로 확정한다.

### 실행 정책

- 회고 화면에 들어갈 때 로드하고, 화면을 나가거나 앱이 백그라운드로 가면 해제한다.
- 추론 모드(thinking)는 끄고, 스트리밍과 취소를 지원한다.
- 컨텍스트 길이, 샘플링 같은 파라미터는 스파이크 결과로 정한다.

### 인터페이스

- 회고 문장 생성은 `narrate(facts)` 인터페이스 뒤에 둔다. 구현은 llama.rn 구현과 가짜 구현 두 가지이고, 도메인·화면 테스트는 가짜 구현으로 돌린다.
- 프롬프트는 버전으로 관리하고, 회고 스냅샷에 그 버전을 기록한다.

### 평가 하네스(PC 로컬 스크립트, CI 아님)

- node-llama-cpp로 폰과 같은 GGUF 파일, 프롬프트, GBNF 문법을 쓴다. Windows와 macOS 양쪽에서 돈다.
- 입력은 고정된 facts 스냅샷 약 20개다. 직전 기간 없음, 기록 적음, 예산 초과, 고정비 비중이 큼 같은 경계 사례를 포함한다.
- 자동 점검 항목: 스키마 통과, 참조한 키가 facts에 있는지, 숫자·한글 수사가 없는지, 문장 길이, 금지어
- 사람 채점 항목: 자연스러움, 고른 사실이 적절한지, 톤. 채점 기준표를 둔다.
- 결과로 모델 비교표를 만들어 README에 싣는다.

## 7. 데이터 모델(초안)

금액은 원 단위 정수다. 날짜는 기기 로컬 시간 기준 `YYYY-MM-DD` 문자열이고, 한 주의 시작은 월요일이다.

| 엔티티 | 주요 필드 |
|---|---|
| Transaction | id, type(expense·income), amount, date, categoryId, reasonTagId?, satisfaction?(regret·neutral·satisfied), memo?, paymentMethod?(card·cash·transfer), isFixed, createdAt, updatedAt |
| Category | id, type(expense·income), name, sortOrder, hidden, isDefault |
| ReasonTag | id, name, sortOrder, hidden, isDefault |
| Budget | month(`YYYY-MM`), total, categoryBudgets(categoryId → amount) |
| Retrospective | id, kind(weekly·monthly), periodStart, periodEnd, facts, output, modelId, promptVersion, createdAt |
| 설정(MMKV) | 사용 모델 ID, 다운로드한 모델 목록 등 |

| 테스트 | Jest + React Native Testing Library 14, E2E는 Maestro |
| 도구 | ESLint, Prettier, husky, commitlint |

Android만 대상이므로 Windows와 macOS 양쪽에서 개발·빌드할 수 있다.

## 9. 테스트 전략

- **단위(Jest)**: 지표 계산기, 예산 일할, 날짜와 주 경계, 금액 포맷터, 플레이스홀더 렌더러, GBNF 생성기, 한글 수사 검사기, 백업 스키마. 핵심 원칙을 지키는 부분이라 TDD로 만든다.
- **컴포넌트(RNTL 14)**: 입력 폼의 3번 탭 흐름, 회고 화면의 상태(생성 중 / 완료 / 폴백 / 기록 부족)
- **E2E(Maestro)**: 입력 → 내역 → 회고 열람
- **LLM**: 평가 하네스(6장)

## 10. 위험과 가정

| 위험·가정 | 대응 |

| 2B급 모델의 한국어 문장 품질 | 평가 하네스로 모델을 비교하고 대안 모델로 교체 |

## 12. 작업 순서(기본안)

디자인 시스템이 배포되기 전에는 UI와 무관한 계층을 먼저 만든다.

1. **LLM 스파이크**: S24+에서 llama.rn과 후보 모델의 로드 시간, 토큰 속도, 메모리, 플레이스홀더 GBNF 동작을 측정한다. 가장 큰 불확실성이라 가장 먼저 한다.
2. **프로젝트 부트스트랩**: RN CLI, pnpm, TypeScript, 린트, Jest
3. **도메인 계층**: 거래·카테고리·예산 스키마(drizzle), 지표 계산기, 예산 일할, 포맷터(TDD)
4. **회고 파이프라인**: facts → GBNF 생성 → `narrate` → 사후 검사 → 렌더러, 평가 하네스
5. **UI**(디자인 시스템 배포 후): 입력 폼, 홈, 내역, 회고, 설정
6. **마무리**: 모델 관리, 백업, E2E

## 13. 결정 기록

| 결정 | 이유 |
|---|---|
| 입력은 폼만 둔다(자연어 입력 제외) | 금액과 카테고리 같은 정형 입력은 폼이 자연어보다 빠르고, 자연어 파서는 구현 난이도만 높인다. 입력 구조화는 비정형 텍스트가 들어오는 카드 알림 파싱에서 보여주는 편이 더 설득력 있다 |
| 숫자는 플레이스홀더로만 쓴다 | 사후 검증과 달리 "LLM은 숫자를 쓸 수 없다"가 구조적으로 보장되고, 테스트로 증명할 수 있다. 증감 방향도 계산 결과라서 코드가 쓴다 |
| 기준 기간을 달력 월 하나로 통일한다 | 월간 회고를 달력 기준으로 정했기 때문에, 예산 주기와 어긋나지 않도록 시작일 설정을 없앴다 |
| 완전 로컬로 만든다 | "금융 데이터가 기기 밖으로 나가지 않는다"가 로컬 LLM의 설득력이다. 서버를 붙이면 범위가 두 배가 된다 |
| Android만 지원한다 | 사용자 본인 폰(S24+) 전용이다 |
| 런타임은 llama.rn | New Architecture를 네이티브로 지원하면서 JSON 스키마·GBNF 제약 디코딩을 하는 사실상 유일한 크로스 플랫폼 런타임이다. Gemini Nano는 대상 기기에서 쓸 수 없고, ExecuTorch는 제약 디코딩이 없다 |
| 회고는 끝난 기간만 만든다 | 진행 중인 데이터로 결론을 내리지 않는다 |
| 폴백은 지표와 차트만 보여준다 | 템플릿 문장 생성기를 따로 만들면 문장 생성기가 두 벌이 된다 |
| 금액 표기를 `32,000원`으로 통일한다 | 화면마다 표기가 달라지지 않게 한다 |
